# ADR-001: Exceptions and Error Propagation Policy

**Rule basis:** 65, 66, 70, 29. **Status:** Accepted.

## Context

Fallible operations pervade the stack: verification, decoding, assembly,
execution, GC slow paths. Native C++ exceptions on hot paths impose unwind
tables, inhibit optimization, and make control flow opaque — the laws
forbid them there, and guest-language exceptions must not be native
exceptions.

## Options considered

1. Native exceptions with catch-at-boundary — rejected: forbidden on hot
   paths (Rule 65); unwind cost and flow opacity.
2. Error codes (int errno-style) — rejected: no payload, no composition,
   callers ignore them.
3. **`Result<T> = std::expected<T, Diagnostic>` with `fail()`/`ok()` helpers
   — accepted.**

## Decision

Every fallible core API returns `Result<T>`; the `Diagnostic` carries an
`ErrorCode`, a message and an optional source position. Guest exceptions are
runtime values (`Throw`/`TryBegin`/`TryEnd` UGB opcodes), never native
unwinding. Compiler failures degrade performance, never abort the program
(Rule 29); the sole documented caveat is EXC-001 (host OOM).

## Consequences

- Correctness impact: error paths are explicit at every call site; the
  compiler enforces inspection (nodiscard semantics of expected).
- Performance impact: hot paths compile to a flag check on the expected
  state; no exception tables.
- Enforcement: lint forbids `throw` in the core library.

# ADR-002: T0 Dispatch — Computed Goto With a Single-Writer Published Table

**Rule basis:** 57, 72, 29. **Status:** Accepted.

## Context

Direct-threaded dispatch needs `&&label` addresses (GNU extension). The
table cannot be constexpr (label addresses are function-local state). A
lazily-initialized function-local static array shared across interpreter
instances is a data race if two threads first-execute concurrently.

## Options considered

1. Per-instance table built in the constructor — impossible: labels live in
   `execute()`, not the constructor.
2. Lazy init with a plain `if (table[0] == nullptr)` guard — rejected:
   formally a data race across instances.
3. **Function-local static table + `std::atomic<uint8_t>` state
   (0=uninit / 1=building / 2=ready), single writer via
   `compare_exchange_strong`, publication with release store, readers
   acquire-spin until ready — accepted.**

## Decision

After initialization the table is process-global immutable data — the exact
category Rule 57 allows. The first executor builds the table and publishes
it; no thread can observe a partially built table (acquire/release pairing).
The spin is bounded by the microseconds the builder runs.

## Consequences

- Correctness: race-free by the C++ memory model.
- Performance: dispatch cost unchanged (one indirect branch); init cost is
  once per process.
- Portability: GCC/Clang only; other toolchains get an explicit startup
  refusal (EXC-002) rather than a silent, untested fallback.

# ADR-003: IR Edges Are 32-Bit Indices, Never Pointers

**Rule basis:** 48, 52, 67. **Status:** Accepted.

## Context

Sea-of-Nodes graphs mutate heavily (rewriting, DCE, inlining). Pointer
edges dangle across node storage reallocation, defeat serialization
(persistent IR, Rule 64), and bloat nodes.

## Decision

`NodeId = uint32_t`; `kNoNode` sentinel; every edge (data, control, effect,
reverse effect) is an index into one dense node store. Operand lists use
`SmallVector<T, 4>` inline storage. Reachability dataflow uses `SparseSet`
(Rule 51). Raw pointer edges are forbidden and lint-checked.

## Consequences

- Cache efficiency: nodes are compact; edge chasing is index arithmetic.
- Realloc safety: growing the node store cannot invalidate edges
  (regression-tested).
- Serialization: persistent IR (J4, Rule 64) can memcpy-emit the store.

# ADR-004: Capability Negotiation in the UGB Format

**Rule basis:** 3, 6, 7, 10. **Status:** Accepted.

## Context

Guest languages differ in what they need (FFI, extensions, exceptions).
Silent misexecution of an unsupported feature is the worst failure class in
the spec.

## Decision

- A closed `Capability` enum with a `CapabilitySet` bitset vocabulary.
- Every UGB method records `required_capabilities` (raw ids in the binary
  format); the module records the union mask.
- The engine advertises `engine_advertised_capabilities()`; at load,
  verification rejects unknown capability ids, and the engine safely rejects
  (with telemetry) methods whose requirements exceed the advertisement.
- Extensions are namespaced `extension.<language>.<feature>` + version,
  grammar-checked by the verifier.

## Consequences

- A method requiring FFI cannot execute on an engine without FFI hooks — it
  fails at load with a named diagnostic.
- Format v2 bumps the minor version; v1 payloads decode with documented
  defaults; incompatible versions are rejected, never loaded best-effort.

# ADR-005: Numeric Semantics — Traps, IEEE Flow, Saturating Conversion

**Rule basis:** 110, 4, 34. **Status:** Accepted.

## Context

The T0 interpreter previously (a) returned a sentinel for "not a double"
that collided with legitimate NaN values, (b) substituted 0.0 for
divide-by-zero, (c) used `static_cast<int64_t>` for float-to-int (UB on
out-of-range/NaN), and (d) checked Smi overflow after signed-overflow UB had
already happened. All four are silent misexecution or UB on guest inputs.

## Decision

1. Type test and value extraction are separate (`as_double(v, out) → bool`);
   no value doubles as a sentinel.
2. Float arithmetic is IEEE-exact: inf/NaN/signed zero flow; division by
   zero is IEEE, never substituted.
3. Float-to-Int conversion is saturating (NaN→0, clamped otherwise) — defined
   for every input.
4. Integer arithmetic uses overflow-checked builtins; Smi overflow is a
   defined guest-visible trap, distinct from type errors. Every typed
   (speculative) form falls back to the canonical semantics inline before
   any error is raised (Rule 34).

## Consequences

- No UB is reachable from guest data in the arithmetic paths.
- Semantics are pinned by `docs/guest-semantics.md` and locked by the
  numeric regression suite; any change to them requires a guest-semantics
  doc update in the same PR (Rule 137) and an oracle-impact review.
